# mcp-savvy 0.1.4

**Status:** release candidate.

## Short version

mcp-savvy can now complete interactive AgentCore OAuth when authorization is returned either as a Gateway `-32042` URL elicitation or as an AWS for SAP Runtime `USER_FEDERATION` result. It starts the local callback before opening the browser, binds the completed session to the current user, retries the tool once, and prevents duplicate responses from opening multiple browser flows.

Set `MCP_SAVVY_COMPLETE_SESSION_URL`, upgrade to `mcp-savvy@0.1.4`, and restart/reconnect the MCP server process.

## Why this changed

AgentCore does not expose every resource-authorization challenge in the same JSON-RPC shape:

- Gateway OAuth targets use error code `-32042` with `error.data.elicitations`.
- The tested AWS for SAP Runtime uses a successful tool-result envelope with `result.structuredContent.result.data.requires_user_action === true` and `auth_url`.

Version 0.1.3 recognized only the Gateway form. A host could display the Runtime URL, but mcp-savvy had not started its `localhost:33424` listener. The provider authorization could complete while the final browser redirect failed with `ERR_CONNECTION_REFUSED`.

## How it works

When `MCP_SAVVY_COMPLETE_SESSION_URL` is configured:

1. The response interceptor correlates either authorization shape to the original `tools/call`.
2. mcp-savvy validates the HTTPS authorization URL and PAR-style `request_uri`.
3. It binds a one-shot listener to `127.0.0.1:33424` before opening the browser.
4. The callback accepts only the configured path and requires `session_id` to exactly match `request_uri`.
5. mcp-savvy sends `{sessionUri}` with the current user Bearer JWT to the HTTPS completion endpoint.
6. The endpoint calls AgentCore `CompleteResourceTokenAuth` to bind the flow to the initiating user.
7. mcp-savvy retries the original tool call once.
8. Overlapping duplicate responses for the same request are dropped while completion is active. A sequential challenge after retry exhaustion is forwarded without opening another browser.

The second callback is separate from the first OIDC/PKCE sign-in callback. Port 33423 uses PKCE and OAuth `state`; port 33424 uses exact one-time session-URI correlation plus an authenticated completion request.

## Included changes

- Recognize Runtime `requires_user_action` / `auth_url` tool results.
- Generalize Gateway-only terminology to AgentCore resource authorization.
- Expose retry availability to response interceptors before side effects.
- Serialize ownership of a request ID during asynchronous response interception.
- Document callback configuration, one-time URL behavior, local-build activation, and troubleshooting.
- Add a deployable Okta-ingress/AWS-for-SAP service-identity scaffold. This example is intentionally separate from the externally validated Runtime `USER_FEDERATION` flow and does not claim named-user SAP propagation.
- Improve release safety by scanning tracked index/worktree content and untracked non-ignored files for secrets.
- Keep the npm publication allowlist restricted to `package.json`, `README.md`, `LICENSE`, and `dist/**`.

## Security notes

- Callback listeners bind to `127.0.0.1`, never all interfaces.
- Authorization URLs, session URIs, bearer tokens, and callback query strings are not logged or persisted.
- The completion endpoint must validate the user JWT and call `CompleteResourceTokenAuth`; a cosmetic localhost success page is not sufficient.
- One-time authorization URLs must not be refreshed or reopened. Start a new MCP tool call to obtain a fresh flow.
- Same-host processes remain inside the local OS-user trust boundary; mcp-savvy does not claim isolation from code running as the same user.
- Source maps are published and contain public project source content with relative paths. They contain no environment values found by the scanner.

## Upgrade

```json
{
  "command": "npx",
  "args": ["-y", "mcp-savvy@0.1.4"],
  "env": {
    "MCP_SAVVY_REMOTE_URL": "https://your-agentcore-endpoint.example.com/mcp",
    "MCP_SAVVY_OIDC_ISSUER": "https://your-issuer.example.com",
    "MCP_SAVVY_CLIENT_ID": "your-public-client-id",
    "MCP_SAVVY_COMPLETE_SESSION_URL": "https://your-api.example.com/complete-session"
  }
}
```

After changing the package version or local build, fully restart/reconnect the MCP server. Existing stdio processes do not reload changed JavaScript.

## Known boundaries

`MCP_SAVVY_COMPLETE_SESSION_URL` is a feature gate. Without it, authorization responses are forwarded unchanged and the port-33424 callback is not started. Deployments are responsible for registering the exact loopback return URL on each relevant AgentCore Gateway or Runtime workload identity.
